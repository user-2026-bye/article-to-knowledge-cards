# Make Knowledge Cards（知识卡片制作）

## 概述

将用户粘贴的文章或本地 Markdown/TXT 文件提炼为 5~8 张知识卡片。每张卡片只讲一个知识点，卡片之间相互独立，便于学习、背诵与复习。

## 使用流程

### 1. 获取原文

- 用户直接粘贴文本 → 直接使用该文本。
- 用户给出本地 `.md` / `.txt` 文件路径 → 读取文件内容后再继续。
- 输入为 URL、PDF、Word 等其它形式 → 礼貌说明暂不支持，请用户改为粘贴文本或提供 .md/.txt 文件。

### 2. 通读并提取候选知识点

通读全文，列出真正重要、值得记住的知识点。同时满足以下标准才保留：

- 对理解全文主题必不可少；
- 包含具体信息（数字、定义、机制、结论、步骤、对比）；
- 独立拿出来仍有意义。

只提取原文明确写出的内容。原文没有的信息（数据、细节、背景、结论）一律不得编写。

### 3. 去重与合并

- 删除表述重复或语义相同的知识点；
- 把分散在原文各处但属于同一知识点的内容合并进同一张卡片；
- 合并后再次检查是否仍有重复。

### 4. 确定卡片数量（5~8 张）

- 按重要性排序，输出 5~8 张卡片；
- 若去重后真正重要的知识点不足 5 个，输出实际数量，并在输出块内「共 N 张」之后另起一行写明「原文信息有限，仅提炼出 N 个独立知识点」；
- 严禁为凑满数量而加入次要内容或编造内容。

### 5. 撰写每张卡片

严格使用以下模板（每张卡片只讲一个知识点）：

```markdown
### 卡片 N：<一句话标题>
- **核心知识**：<一句话概括本知识点>
- **简明解释**：<2~4 句话讲清含义、要点或机制>
- **例子或自测问题**：<优先给出原文中的例子；原文没有可用例子时，出一道针对本知识点的自测题>
```

- 标题要短且有区分度，能概括该知识点；
- 「简明解释」可以重述、改写原文信息，但不得添加原文没有的内容；原文表达不完整或信息不足时，如实说明，不要自行补充；
- 「例子」必须来自原文，不得编造；原文没有合适例子，或知识点本身就是原文的单个陈述（此时例子易与「简明解释」重复）时，改出自测题（提问句，附简要参考答案）；
- 自测题的参考答案也只能使用原文信息，不得补充原文之外的内容。

## 输出格式

全部卡片一次性输出，放在同一 Markdown 块中，便于用户直接复制：

```markdown
# 《<源文章标题或文件名>》知识卡片

**共 N 张**

### 卡片 1：<标题>
...
```

- 原文没有标题时，用文章内容概括一个简短标题（如「水的沸点与气压」），不要使用「无标题」之类的占位符；
- 文章自带标题与文件名不一致时，优先使用文章自带的标题；
- 卡片字段标签（核心知识／简明解释／例子或自测问题）随输出语言翻译，例如英文输出时使用 Core knowledge／Plain explanation／Example or self-test question；
- 输出语言默认与原文一致；用户另有要求时按用户要求执行（如指定中文、英文或双语）。
- 原文信息过少、提炼不出独立知识点时，明确告知用户信息不足，不要强行生成卡片。
- 原文存在矛盾内容时，如实呈现原文的说法，不要自行调和或替用户做选择。

## 不支持的内容

遇到以下需求明确拒绝，不做替代实现：

- 网页抓取（用户只提供 URL 时）
- PDF 解析
- Anki / 闪卡格式导出
- 图形界面

## 输出前自查

- [ ] 每张卡片只讲一个知识点
- [ ] 卡片中的每个事实都来自原文，没有编造
- [ ] 卡片之间没有重复内容
- [ ] 数量在 5~8 之间；不足 5 个时已如实说明
- [ ] 例子来自原文，或已改为自测题
